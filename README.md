# 社区公益集市：摊主审核、摊位分配、收款与捐赠平台

面向社区举办公益集市的全流程管理系统，覆盖 **摊主报名 → 社区审核 → 智能摊位分配 → 入场二维码/物资清单 → 现场核销巡检 → 收款与捐赠核对 → 投诉/异常处理 → 客流统计 → 统一活动档案 → 复盘与居民公示**。

技术栈：**Vue 3 + Vite + Element Plus + ECharts**（前端）、**Spring Boot 3 + Spring Data JPA + ZXing**（后端）、**MySQL 8**（数据库）、**Docker Compose**（一键启动）。

## 一、功能清单

| 角色 | 功能 |
| --- | --- |
| 摊主 | 在线报名（售卖品类、食品资质、公益捐赠比例、用电需求、桌椅需求、亲子摊位、收款方式）；查看审核结果与规则提示；查看入场二维码、核销码和物资领取清单；个人信用分与历史捐赠 |
| 社区管理员 | 活动与摊位布局管理（分区、人流、供电回路、耐噪、亲子位）；报名审核（五类摊位活动规则自动校验）；一键智能分配/人工调换；摊主信用档案；活动状态管理；发布居民公示 |
| 现场工作人员 | 扫码核销入场、物资发放确认；现场检查实际售卖内容、临时换品审批、提前离场登记；收款流水登记；按承诺比例自动核算应捐、实缴核对；投诉登记与办结；六类异常登记处理（自动扣信用分）；客流按时段统计 |
| 居民（免登录） | 浏览已公示活动：捐赠总额、资金用途、摊主履约与捐赠明细、异常处理情况；在线提交投诉 |

### 核心业务规则

- **报名审核规则**（提交即自动校验，命中则不允许通过，须驳回补正）：
  - 食品类必须填写食品经营许可/健康证资质；
  - 公益义卖承诺捐赠比例不低于 50%；商业摊位不低于 5%；
  - 用电超过 1500W 须社区统筹；噪音/油烟须入耐噪专区。
- **智能摊位分配**：
  - 综合评分 = 信用分 + 历史累计捐赠 + 本次承诺捐赠比例 + 公益属性加权 − 食品风险降权，高评分优先高人流位置；
  - 硬约束：单摊功率、同一供电回路总容量（防超载）、食品必须入 F 专区、噪音必须耐噪位、桌椅数量匹配摊位面积；
  - 软约束：公益摊位优先主通道、亲子摊优先 K 亲子区、同类品类避免相邻（无法避免时给出冲突提示）；
  - 支持管理员人工拖拽调换，调换时重新校验全部约束。
- **信用联动**：售卖与报名不符（−15）、捐赠与流水不一致（−10）、提前离场（−8）、用电超载/食品资质等异常实时扣减摊主信用分；食品资质类异常同时标记食品风险，影响其以后所有活动的摊位位置。
- **捐赠核对**：应捐金额 = 收款流水合计 × 报名承诺比例；实缴不一致自动登记「捐赠金额与流水不一致」异常；一致时累计进摊主历史捐赠。
- **统一活动档案**：报名、审核、摊位、收款、捐赠、检查、换品、投诉、异常、客流、公示全部归属同一活动可追溯。
- **复盘建议**：根据品类分布、异常类型、供电负载、未办结投诉等自动生成下次招商建议。

## 二、一键启动（Docker Compose，推荐）

前置要求：已安装 Docker 20+ 与 Docker Compose v2。

```bash
cd 154-a
docker compose up --build -d
```

启动后：

| 服务 | 地址 |
| --- | --- |
| 前端页面（含居民公示页） | http://localhost |
| 后端 API | http://localhost:8080 |
| MySQL | localhost:3306（库 charity_market，用户 cm / 密码 cm123456） |

首次启动自动建表并写入一场示例活动（18 个摊位、5 条待审核报名）。停止用 `docker compose down`，保留数据；连数据一起清除用 `docker compose down -v`。

> 入场二维码内容为 `http://localhost/checkin?code=xxxxxx`，由后端环境变量 `PUBLIC_BASE_URL` 控制；如部署到服务器，请在 `docker-compose.yml` 中改为实际访问域名。

## 三、本地开发启动

### 1. 准备 MySQL 8

```sql
CREATE DATABASE charity_market CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'cm'@'%' IDENTIFIED BY 'cm123456';
GRANT ALL PRIVILEGES ON charity_market.* TO 'cm'@'%';
FLUSH PRIVILEGES;
```

### 2. 启动后端（端口 8080）

```bash
cd backend
# 数据库连接通过环境变量覆盖，默认 localhost:3306 / cm / cm123456
mvn spring-boot:run
# 如 MySQL 在其他端口： DB_PORT=3307 mvn spring-boot:run
```

后端打包：`mvn clean package -DskipTests`，产物 `target/charity-market.jar`。

### 3. 启动前端（端口 5173，已配置 /api 代理到 8080）

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 http://localhost:5173 。生产构建：`npm run build`（产物在 `frontend/dist`）。

## 五、建议的功能验证路径

1. **登录** `admin`，在「报名审核」页看到 5 条报名与规则提示（赵记烤冷面无食品资质、王姐卤味缺资质、功率超标提示）。
2. 摊主 `vendor3` 登录 → 摊位报名 → 补传食品资质与证号重新提交；管理员对赵记烤冷面点「通过」会被规则拦截，驳回后通过其余 4 家。
3. 「摊位分配」页点 **一键智能分配**：星公益义卖（评分最高）→ A 区高人流；暖手心作（亲子）→ K 亲子区；时光旧物仓（用电）→ B 区带电摊位；王姐卤味（食品/噪音/用电）→ F 食品专区；可查看每个分配的理由与回路负载。
4. 摊主 `vendor1` 登录 →「我的入场凭证」查看二维码、核销码与物资清单。
5. 工作人员 `staff` 登录 →「现场核销与巡检」：输入/扫码 6 位核销码 → 核销入场 → 发放物资 → 现场检查、登记临时换品。
6. 「收款与捐赠」：给摊位登记两笔流水（如 600+400），系统自动按 10% 算出应捐 100 元；故意少缴 80 元核实 → 自动出现「捐赠与流水不一致」异常并扣 10 分（可在摊主信用档案看到 vendor1 信用下降）。
7. 「投诉处理」「异常管理」登记办结投诉与用电超载异常；「客流统计」录入分时段客流并查看柱状图。
8. 「活动统一档案」查看一个活动内的全量记录；「复盘与公示」查看公益目标达成图、品类/异常分布、用电负载、每位摊主履约评分与下次招商建议，然后发布公示。
9. 浏览器无痕窗口打开 **居民公示页**：查看总捐赠、用途、摊主履约与异常处理，并可匿名提交投诉。
